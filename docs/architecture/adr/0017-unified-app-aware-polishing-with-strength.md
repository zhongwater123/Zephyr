# ADR-0017：统一的应用感知智能润色与三档强度

- Status: Accepted
- Date: 2026-08-28
- Deciders: Project maintainers
- Drivers: 用户需要的是一个由模型结合当前应用自主判断的智能润色助手，而不是需要理解和维护固定画像的规则系统；MVP 还需要简单、可感知的 1–3 档介入强度
- Related features: FEAT-SMART-DICTATION
- Assumptions: ASM-SD-01, ASM-SD-02, ASM-SD-08, ASM-SD-10
- Evidence: 2026-08-28 用户明确要求参考 Typeless 的智能成稿体验，允许模型依据当前应用和完整表达自主决定语气、结构和要点提取，并确认先按三档强度完成 MVP
- Supersedes: ADR-0015, ADR-0016
- Superseded by: None

## 背景

上一版 MVP 把目标 EXE 映射为 `general`、`chat`、`office` 或 `coding_request`，再加载四份隔离 Prompt。这个方案可复现，但把产品能力降成了静态分类器：浏览器只能回退 `general`，新增应用需要维护映射，用户还需要理解逐应用画像覆盖。更重要的是，固定画像在模型调用前丢失了应用身份，限制了模型根据完整口述和使用场景进行泛化判断。

用户确认的产品目标是一个统一的 AI 智能润色助手。应用负责提供本次冻结的 ASR 原文、目标应用身份和用户选择的润色强度；模型负责在不改变事实和意图的前提下自主完成去口语冗余、疑似 ASR 错词纠正、语气适配、结构整理和要点提取。

## 决策

1. 快捷键 A 继续固定启动 `SmartDictation`，录音、ASR final、取消、原文兜底和 Delivery 控制链路不变。
2. MVP 不再维护内置 EXE→画像映射、逐应用画像覆盖或四种 Prompt。删除该固定 Router 选择步骤。
3. TextProcessing 使用一份应用拥有、版本化且带哈希校验的统一语义 Prompt。JSON Output envelope、字符校验和数据封装仍由 adapter 负责。
4. 每次处理把以下冻结数据传给模型：完整 ASR 确认原文、目标可执行文件名、可用时的应用名称、全局润色强度。窗口标题、页面内容、屏幕、聊天历史、文档正文、源代码和剪贴板内容不进入 MVP Prompt。
5. 目标应用身份只是上下文信号，不是固定模式。模型必须同时依据原文意图判断合适的语气和结构，不能因为应用名称就虚构场景、事实或用户要求。
6. 全局润色强度为 1、2、3 三档，默认 2：
   - 1 档：轻度清理，主要去除无意义语气词、重复和明显语病，尽量保持原句式与口吻。
   - 2 档：标准智能润色，在保持事实、立场和语气的基础上改善清晰度、连贯性和场景表达；遇到明确或自然形成的并列意图时自动提取要点。
   - 3 档：允许更深的重组、归纳和层次化表达；仍不得新增事实、承诺、结论、需求或技术决策。
7. 强度表示允许的最大介入程度，而不是强制改写量。原文已经清晰有序时，模型应少改；单一短句不得为了显示能力而强制分点。
8. 默认模型继续为关闭思考模式的 `deepseek-v4-flash`，非流式 JSON Output、20 秒硬截止、8000 Unicode 字符上限、无重试、原文兜底和一次性整体粘贴保持不变。
9. HotwordAgent 与 TextProcessing 继续引用同一预置 DeepSeek credential，但用途授权、信任检查和审计保持隔离。员工 UI 不暴露 API Key。
10. History/Incident 记录强度、Prompt 版本、稳定原因码和耗时，不记录完整 Prompt 或未经既有内容授权的数据。旧的 `profile_id` 不再作为当前处理元数据。

## 结果

- 浏览器、聊天、办公和编码工具使用同一条处理链路，模型能够同时利用应用身份和完整口述，而不是先被固定画像截断。
- 用户只需要理解一个全局强度设置；默认二档提供可直接感知的整理和要点提取。
- Prompt 迭代和语料评测从四套画像矩阵收敛为“一份统一 Prompt × 三档强度 × 多应用场景”。
- 输出风格比确定性 Router 更依赖模型质量，需要用跨应用语料回归约束事实保持、不过度改写和结构提取。

## 未采用方案

- **继续扩充 EXE 分类和逐应用覆盖：** 增加规则维护和用户理解成本，且不能解决浏览器内多场景问题，不采用。
- **先用模型路由，再调用画像模型：** 增加一次调用、延迟和失效点；MVP 的统一模型本身可以完成场景判断，不采用。
- **传窗口标题或页面/屏幕内容：** 可能提高上下文精度，但扩大隐私和授权边界，MVP 不采用。
- **为每档复制一份 Prompt：** 容易造成规则漂移；强度定义属于统一 Prompt 的稳定输入契约，不采用。

## 验证要求

- 契约测试确认请求同时包含原文、EXE、可选应用名和 1–3 档强度，且不包含窗口标题或其他屏幕内容。
- 配置迁移和前端测试确认旧配置升级后默认二档，三档选择可持久化，员工界面不再出现逐应用画像编辑器。
- Prompt manifest/hash/缺失/篡改测试继续失败关闭。
- 跨聊天、办公、编码和浏览器语料分别评测三档差异、事实保持、明显分点意图和“原文清晰时少改”。
- 真实 Windows 目标环境仍需验证快捷键、DeepSeek 调用、WebView2 设置持久化和多应用整体粘贴。

## Revisit when

- 需要第二种快捷键意图、翻译、Agent 或用户自定义指令；
- 经用户授权后需要窗口标题、页面、选中文本或文档上下文；
- 单次统一调用不能满足延迟、稳定性或场景质量目标；
- 应用开始对外分发，需要重新设计凭据和数据治理边界。
